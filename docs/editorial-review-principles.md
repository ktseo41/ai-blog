# 에디토리얼 리뷰 — 원리 목록

문체(AI 티)가 아니라 **정보 설계**를 심사하는 리뷰의 원리를 모은 문서. 개별 글의 리뷰 기록(사례 로그)은 비공개 작업 저장소에 쌓고, 여기에는 거기서 반복 관찰되어 추려진 원리만 옮긴다.

## 운영 규칙

- **기록 단위는 "a는 r 때문에 b로"이고, 자산은 r이다.** a는 관찰된 현상, r은 왜 문제인가(독자 관점의 비용), b는 고침 방향. b는 상황마다 다른 후보들이 있을 뿐 규칙이 아니다. 리뷰 산출물은 반드시 r을 인용한다.
- 같은 r이 **서로 다른 글 3편 이상**에서 관찰되면 원리로 승격한다. 그 전까지는 후보로 둔다. 사례 1회분으로 만든 규칙은 과적합이다.
- 원리가 충분히 쌓이면(대략 7–10개) 리뷰 체크리스트로 추출한다.

## 승격 원리

서로 다른 글 3편 이상에서 반복 관찰된 것.

| ID | 원리 | 풀이 |
| --- | --- | --- |
| P-01 | **독자 다수의 목적 경로 최단화 (역피라미드)** | 독자가 가장 많이 찾는 답(결론·추천·표)을 앞에 둔다. 방법론·조사 규모·"읽는 법" 안내는 결론 뒤로 보낸다. |
| P-02 | **메타 정보는 가장 바깥 층위에 한 번만** | AI 조사 표기, 조사 시점, 검수 방식 같은 메타는 사이트 층위나 글 끝 출처 절에 한 번만 둔다. 본문 상단 배지·인용 블록·불릿으로 반복하지 않는다. |
| P-03 | **강조 강도 = 정보 중요도** | 볼드·인용 블록·경고 박스는 정보의 중요도와 일치할 때만 쓴다. 절 전체 볼드, 메타 문장 인용 블록은 강조 인플레이션이다. |
| P-04 | **표 밀도 문제의 원인은 이질성** | 표가 답답하면 폭이 아니라 셀 내용의 이질성을 의심한다. 한 열에 성격이 다른 정보가 섞이면 열을 쪼개거나 셀 안 서브리스트로 구조화한다. |
| P-05 | **요약–본문 축자 중복 금지** | 요약(TL;DR·범례·용어집)이 본문 문장을 그대로 반복하지 않는다. 요약은 본문의 압축이지 복사가 아니다. |
| P-06 | **약어·용어는 첫 등장에서 정의하고 표기를 통일한다** | "풀네임(약어)" 형태로 첫 등장에서 정의하고, 이후 한 표기만 쓴다. 공식명과 커뮤니티명, 한글과 영어 음차의 혼재는 데이터(표·툴팁)와 프로즈 양쪽을 한 규칙으로 묶어 잡는다. |
| P-07 | **축약·비일상 용어보다 읽기 쉬운 일상 용어** | 슬랭·내부 약어보다 독자가 첫눈에 아는 말을 쓴다. 꼭 써야 하면 일상어로 먼저 풀고 괄호에 붙인다. |
| P-08 | **내부 상태를 독자에게 노출하지 않는다** | 작업 중 표시(신규 마커, 초안 메모, 제작 방침 문장, 워크플로 언급)는 발행본에서 지운다. 독자는 결과물만 본다. |
| P-09 | **구조가 말한 것을 텍스트로 반복하지 않는다** | 표·목록이 이미 보여주는 것을 앞뒤 문장으로 예고·복창하지 않는다. |
| P-10 | **동종 표는 동일 그리드** | 같은 성격의 표는 열 구성·셀 포맷·단위 표기를 맞춘다. 문서 전반과 후반이 같은 정보를 다르게 표시하지 않는다. |
| P-11 | **인용이 참조하는 값은 같은 화면에 있어야 한다** | 본문이 "위 표의 수치"를 근거로 삼으면 그 수치가 실제로 그 표에 있어야 한다. 요약 표에서 빠진 값을 본문이 참조하지 않는다. |

## 후보 원리

관찰 1–2회. 승격 전이지만 리뷰 시 참고한다.

| 후보 | 풀이 |
| --- | --- |
| 문장당 정보 하나 | 도입 문장에 목적·범위·시점·방법을 한꺼번에 싣지 않는다. |
| 연구 과정을 서사화하지 않는다 | "처음엔 A를 봤다가 B로 갔다"는 회고는 결론에 기여하지 않으면 뺀다. |
| so-what을 저자가 먼저 뽑아준다 | 데이터를 나열하고 해석을 독자에게 맡기지 않는다. |
| 핵심 결론과 부연·근거의 독자층 분리 | 결론만 원하는 독자와 근거까지 원하는 독자가 다른 층에서 읽게 배치한다. |
| 독자가 모르는 대상과의 대조로 글을 열지 않는다 | "X와 달리 이 글은…"으로 시작하면 X를 모르는 독자에겐 부정 정의만 남는다. |
| 범례는 본문의 실제 상태를 기술한다 | "파란 글씨는 눌린다"고 했으면 실제로 그 대상 전부가 눌려야 한다. |
| 독자가 소비하는 1차 상품을 방법론보다 앞에 둔다 | 제작 산출물(반응·표·추천)이 주인공이고 제작 방식 회고는 부록이다. |

## 원리가 아닌 것 (표기·기술 컨벤션)

- 음수는 ASCII `-`로 쓴다 — U+2212 최소부호는 일부 폰트에서 깨진다.
- 마크다운 볼드가 `)**` 뒤에 한글이 바로 붙으면 닫히지 않는다 (CommonMark flanking 규칙). 공백이나 문장부호로 분리한다.
- 순수 문체 문제(어순·어미·번역투)는 이 문서가 아니라 humanize 단계에서 다룬다.
- 템플릿·빌드 스크립트에서 유래한 결함은 글마다 재발한다 — 글이 아니라 템플릿 단계에서 잡는다.
