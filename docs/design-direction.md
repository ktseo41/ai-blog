# 디자인 방향 (2026-07-20)

research-ai-design-tools.md의 결론을 실행에 옮기기 위한 문서. "AI UI slop" 회피의 핵심은 **도구에 맡기기 전에 방향을 사람이 문서로 정하는 것** — 이 문서가 그 역할이다. frontend-design 스킬·tweakcn 등으로 실행할 때 이 문서를 제약 조건으로 준다.

## 핵심 원칙

1. **컴팩트 + 가독**: 여백은 작게, 그러나 본문 타이포는 절대 희생하지 않는다. 밀도는 여백·컴포넌트 크기에서 얻고, 폰트 크기·행간·줄폭은 가독 기준을 지킨다.
2. **radius 최대 4px**: 모든 모서리는 0·2·4px 세 단계만. 알약 버튼, 큰 라운드 카드 금지.
3. **콘텐츠가 주인공**: 장식적 요소(그라디언트, 그림자, 히어로 배너) 최소화. 블로그의 볼거리는 글과 데모다.
4. **slop 회피 금지 목록**: indigo/보라 그라디언트 배경, 유리morphism, 큰 라운드 + 두꺼운 그림자의 stat 카드, 제목마다 이모지, 무의미한 아이콘 나열 — 전부 금지. (X 여론 조사에서 "AI가 만든 UI" 지문으로 지목된 패턴들)

## 토큰 (초안)

### radius
- `--radius-0: 0` (기본 — 표, 코드 블록, iframe)
- `--radius-s: 2px` (인라인 코드, 태그)
- `--radius-m: 4px` (버튼, 입력, 카드 최대치)

### 간격 — 4px 스케일, 컴팩트 쪽으로
- 스케일: 4 / 8 / 12 / 16 / 24 / 32 / 48
- 본문 문단 간격: 0.75em–1em (템플릿 기본보다 축소)
- 섹션(h2) 위 여백: 32px 수준, 아래는 12px
- 리스트 항목 간격: 최소화 (li 간 margin 없음, 줄간만)
- 헤더·푸터도 컴팩트: 현재 푸터 `6em` 하단 패딩 같은 과잉 여백 제거

### 타이포
- 본문: **16px(1rem) 전 해상도 고정** (17px 데스크톱 확대는 실물 확인 후 "너무 크다"로 철회, 2026-07-20). 컴팩트를 이유로 15px 이하로 내리지 않는다 (한국어는 라틴보다 자형이 조밀해 작으면 급격히 피로해짐).
- 행간: 본문 1.65–1.75 (한국어 기준), 제목 1.3.
- 줄바꿈: 전역 `word-break: keep-all` + `overflow-wrap: break-word` — 한글 어절 단위 줄바꿈(표 셀에서 "네이/버"식 글자 끊김 방지), 초장문 토큰(URL 등)만 강제 개행.
- 줄폭: 본문 최대 65–75자 → `max-width` 42–46rem 수준. 컴팩트는 좌우 패딩 축소로 얻지, 줄폭을 늘려서 얻지 않는다.
- 폰트: **나눔고딕 또는 나눔스퀘어** (사용자 지정, 2026-07-20). 기본안은 본문 나눔고딕 + 제목 나눔스퀘어 조합, 단순하게 가려면 나눔고딕 단일. woff2 self-host + `system-ui` 폴백, 외부 CDN 금지(성능·완결성). 나눔스퀘어는 본문 장문 가독을 한 번 검증하고 채택(자형이 각져서 제목엔 강하고 본문엔 호불호).
- 제목 스케일 완만하게: h1 1.5rem / h2 1.2rem / h3 1.05rem (한 단계 축소, 2026-07-20). 큰 제목은 여백을 먹으므로 컴팩트 원칙과 충돌 — 크기보다 weight로 위계 표현.

### 색
- 뉴트럴 그레이 스케일 + **액센트 1색**만. 액센트는 링크·활성 상태에만 사용.
- 배경은 순백/순흑 대신 살짝 튜닝(#fafafa류 / 다크는 추후). 그라디언트 배경 금지.
- 구분은 색면보다 1px 보더 — 컴팩트 밀도와 어울림.

## 컴포넌트 방향

- **글 목록**: 카드 그리드보다 밀도 있는 리스트(제목 + 날짜 + 한 줄 설명). 썸네일은 있으면 소형.
- **표**: 이 블로그 글에 표가 많음(조작법, 도구 비교). 1px 보더, 컴팩트 셀 패딩(6–8px), radius 0.
- **코드 블록·인라인 코드**: radius 2px, 배경은 뉴트럴.
- **AI 명시 배지**: 글 상단 blockquote 대신 작은 배지/한 줄 노트 스타일로 정형화 — 모든 글에 공통.
- **데모 iframe**: 1px 보더, radius 0–2px. 현재 conway 글의 `border-radius: 3px` 인라인 스타일은 토큰으로 흡수.
- **/play 페이지**: 이미 방향 부합(얇은 바 + 풀뷰포트). 다크 배경 유지.

## 화면·DPI 참고

CSS px의 물리 크기는 화면의 논리 PPI(해상도 스케일링 결과)에 따라 다르다 — 맥북 레티나와 외장 모니터에서 같은 16px가 다르게 보이는 건 정상. 대응 원칙:

- 특정 화면에 맞춰 px을 미세조정하지 않는다. 기준(16–17px)을 지키고 **양쪽 화면에서 확인**하는 것을 검수 절차로 삼는다.
- 저 DPI 외장 모니터에서는 macOS가 서브픽셀 AA를 제거한 이후 가는 weight가 흐릿해 보임 → 본문 weight 400 유지, 300대 라이트 웨이트 금지.
- 크기는 rem 기반으로 통일해 사용자 브라우저 설정 확대를 존중.

## 실행 계획

1. 이 문서를 제약으로 frontend-design 스킬 실행 → 템플릿 CSS(global.css 등)를 토큰 기반으로 재작성.
2. 필요시 tweakcn류로 팔레트 탐색하되, 결과는 반드시 위 토큰 체계로 번역해서 반영.
3. 검수: 맥북 + 외장 모니터 + 모바일(390px) 3종 스크린샷 비교, slop 금지 목록 체크.
