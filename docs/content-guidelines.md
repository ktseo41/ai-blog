# 콘텐츠 가이드라인

이 repo는 언제든 public이 될 수 있다는 전제로 쓴다. 발행용 최종본만 반입하고, 반입 전 아래 기준으로 거른다.

## 무엇을 올리는가

"공유할 만한 조사 자료"가 기준이다. 카테고리는 열려 있고, 현재 재고 기준 예시:

- 웹툰·콘텐츠 리뷰 (추천 리스트, 커뮤니티 여론 종합, 영화 평점 정리 등)
- 증시·시황 분석 (공개 소스 기반 브리핑, 섹터 분석, 밸류에이션 방법론 등)
- 직접 만든 실험용 게임·인터랙티브 데모 (WebGL, 신경망 시각화 등)
- 생활 리서치 (호텔 라운지 후기 종합, 스마트홈, 생활 팁 등)
- AI 도구 활용기·기술 가이드

비공개 작업 저장소의 산출물이 소스이며, 항목별 공개 적합성 평가(A: 거의 그대로 / B: 다듬으면 / C: 반입 금지)는 그쪽에서 한다.

로컬 전용 원자료(전문 번역 초안·원문 덤프 등)는 이 레포 안 `ai-blog-raw/`에 둔다. gitignore 대상이라 커밋·배포에 포함되지 않는다. 설명은 `ai-blog-raw/README.md`만 추적한다.

### 외부 공식 발표·타사 글을 다룰 때

전문 번역 재게시보다 **자세한 핵심 정리 + 해설(+ 직접 조사분(연구 등))** 을 `src/content/blog/`에 발행한다. 전문 번역이 필요하면 `ai-blog-raw/`에만 두고 공개 글에는 넣지 않는다.

## AI 콘텐츠 명시 정책

- 각 글에 "AI(모델명)와 함께 조사·정리하고 사람이 검수한 콘텐츠"임을 명시한다. 위치는 도입부가 아니라 **글 끝 "출처" 절 머리 문단**을 권장한다 — 조사 범위·수집 일자와 함께 한 곳에 두면 되고, 상단에 두면 결론 도달을 늦추는 메타가 된다(editorial-review-principles P-01·P-02). 사이트 About에도 운영 방식을 설명한다.
- 단순 "AI가 써준 글"이 아니라 가치가 드러나는 구조를 지킨다: 조사 범위·방법 명시, 출처 링크, 수집 일자, 사람의 판단이 들어간 결론. 이는 정직성 문제이면서 동시에 애드센스의 "가치 없는 AI 생성물" 거절 사유 대응이기도 하다 (research-seo-monetization.md 참조).

## 반입 금지 (C급) — 어떤 커밋에도 넣지 않는다

1. **개인 금융 정보**: 보유 종목의 수량·평단가·자산 대비 비중 등 실포지션. 시황 분석은 되지만 "내 계좌" 수치는 안 됨.
2. **유료 콘텐츠 전사·번역**: 유료 구독 글의 전사·요약 재배포, paywall 기사 전문 번역, 증권사 리포트 과다 발췌.
3. **제3자 콘텐츠 원문 덤프**: 유튜브 자막 전문, 타인 게시물 대량 수집 원본(JSON 덤프 등). 요약·분석물만 가능하며 출처 명시.
4. **개인 정체성·사생활 원자료**: 개인 SNS 계정의 북마크/좋아요 덤프, 문체 프로필, AI 대화 세션 원본·URL.
5. **자격증명·내부 경로**: API 키, 토큰, 로컬 절대경로가 노출된 스크립트 등.

## 반입 시 다듬기 체크리스트 (B급 → 발행본)

- [ ] frontmatter 부여: title / date / tags / description
- [ ] 도입부에 컨텍스트 추가: 왜 조사했는지, 언제 기준 정보인지
- [ ] AI 조사·정리 명시 문구 삽입
- [ ] 내부 작업 흔적 제거: 에이전트/모델 운영 언급, 내부 파일 경로, 작업 지시문 잔재
- [ ] 출처 링크 정리 (원문 발췌는 인용 범위로 축소)
- [ ] 개인정보 스윕: 계좌·평단·위치·핸들·실명
- [ ] 투자 관련 글은 "투자 조언 아님" 고지 추가
- [ ] 이미지: 최적화(압축·리사이즈) 후 반입, 대형 원본은 repo에 넣지 않음

## 글 구조·가독성 체크리스트

발행본이 "읽히는 글"이 되도록 하는 기준. 외부 스킬 `getsentry/skills@blog-writing-guide`에서 **언어와 무관한 구조 원칙만** 추려 한글 블로그에 맞게 옮겼다. 원본의 영어 전용 항목(영어 마케팅 금지어, 영어 문장 리듬 기반 AI 티 등)은 여기 넣지 않는다 — 한글 문체·번역투·AI 티는 아래 "가독성 3단 파이프라인"의 humanize-korean 단계가 담당한다.

### 도입부 (첫 2–3문장)

- [ ] **문제 또는 결론부터 시작한다.** 배경 설명·자기소개·기대감("이번에 흥미로운 걸 다뤄봤다")으로 열지 않는다.
- [ ] 독자가 "이 글이 나한테 왜 필요한지"를 첫 문단에서 안다.

### 구성 (독자의 질문 순서를 따른다)

내 서술 순서가 아니라 독자가 실제로 궁금해하는 순서로 배치한다:

1. [ ] 무슨 문제를 푸는가 (1–2문단)
2. [ ] 실제로 어떻게 작동/전개되는가 (본론, 구체적으로)
3. [ ] 트레이드오프·대안·한계는 무엇인가 (좋은 글과 평범한 글을 가르는 지점)
4. [ ] 나는 어떻게 써보나/따라 하나 (구체적 다음 단계)

### 스키머빌리티 (훑어 읽어도 뼈대가 잡히게)

- [ ] **한 문단 한 아이디어.** 두 논점이 한 문단에 있으면 쪼갠다. 세 문장 문단, 강조용 한 문장 문단 모두 괜찮다.
- [ ] **전환점에서 문단을 끊는다.** "하지만·그런데"로 관점이 바뀌는 지점은 새 문단으로 시작해 시각적 강조를 준다.
- [ ] **H2 제목에 정보를 담는다.** "무엇을 볼까" 같은 빈 제목 대신 "AI 에이전트 모니터링의 핵심 지표"처럼 내용·키워드가 드러나는 제목.

### SEO (검색 유입을 노리는 글에만)

- [ ] **일반론으로 열고 구체(내 결론/도구)로 닫는다.** 앞 절반은 개념·정의·베스트프랙티스 같은 도구 중립 교육 내용, 뒤 절반에서 구체 사례로. 검색엔진은 가이드를 판매 페이지보다 상위에 놓는다.
- [ ] **정의 섹션 하나.** 핵심 용어는 "X란 무엇인가" 절을 둔다 (기본처럼 느껴져도).
- [ ] **FAQ 3–4개.** 롱테일 키워드를 겨냥한 하단 Q&amp;A. 스니펫·"함께 찾는 질문" 노출에 유리.

## 가독성 3단 파이프라인

발행 전 가독성 점검은 층위가 다른 세 단계로 나눠 돌린다. 서로 담당 영역이 겹치지 않는다.

1. **화면·타이포그래피** — 스킬 `typography-scale`(스케일 설계), `critique-typography`(적용 후 진단). 크기 위계·줄높이·대비·토큰 준수를 본다.
  - 한글 주의: critique-typography의 "줄 길이 45–75자"는 라틴 기준이다. 교과서적 적정은 한 줄 25–40자이나, 이 블로그는 표 위주 글이 많아 **본문 폭 900px(한 줄 약 55자)** 로 운영한다 — 표의 서술형 열 폭 확보가 줄 길이보다 체감 가독성에 크게 기여한다는 실측(2026-07-21) 반영.
2. **글 구조·정보 설계** — 위 "글 구조·가독성 체크리스트" + `editorial-review-principles.md`(원리 목록 — 사례 로그는 비공개 작업 저장소). 도입·구성·스키머빌리티·SEO에 더해, 정보의 존재 이유·위치·강조 강도·표 설계를 심사한다. 리뷰는 "a를 b로"가 아니라 "a는 r(원리) 때문에 b 후보 중 하나로" 형식으로 기록하고, 반복 관찰된 r만 원리로 승격한다.
3. **한글 문체 자연스러움** — 스킬 `humanize-korean` + 서브에이전트(`ai-tell-detector`로 탐지, `korean-style-rewriter`로 윤문). 번역투·피동 남용·기계적 병렬·영어 인용 과다 등 AI 티를 내용 불변으로 제거한다. 원문 대조 검증은 `content-fidelity-auditor`.

**적용 우선순위 메모** (실측 2026-07-21, 웹툰·시황 글 2편 통과):

- 읽기 편함에 가장 크게 기여하는 건 1단계(타이포)다. 본문 폭·제목 위계·표 반응형이 실제 체감을 좌우한다. AI 티 제거는 부차적 — "어느 정도 나도 되는" 영역이다.
- 리스트·표 위주 글은 서술 문단이 적어 3단계를 경량으로 지나가도 된다. **다수 소스를 엮은 종합 서술형 글이 3단계의 주 타깃**(문두 요약어·라벨+콜론·영어식 쉼표가 몰림).
- 3단계에서 "정리하면"·"합의되는 지점:" 같은 신호어는 훑어읽기를 돕는 순기능이 있으니 AI 티라고 무조건 지우지 않는다. 읽기 흐름을 해치는 추상·명사화 문장만 골라 편다.
